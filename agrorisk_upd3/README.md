# Агрориск: декадный индекс засухи / суховея / раннего снега

Индекс риска по декадам (1-10, 11-20, 21-конец месяца) для одной точки поля.
Данные — только Open-Meteo, оценка деградации почвы — нейросеть `pinn_model.pt`.
Работать можно из браузера или из командной строки.

```bash
pip install -r requirements.txt
python web.py        # веб-интерфейс
python run.py        # то же самое в консоли
```

Попутно исправлены три ошибки, которые искажали результат:

1. **Единицы ветра.** Open-Meteo по умолчанию отдаёт скорость ветра в км/ч,
   а прежний код считал эти числа метрами в секунду — ветер завышался в 3.6 раза
   и ломал критерий суховея. Теперь единицы задаются явно (`wind_speed_unit=ms`).
2. **Надбавка за ветер в индексе суховея** считалась по максимальному порыву за
   всю декаду. За десять суток порыв выше 15 м/с случается почти всегда, поэтому
   надбавка срабатывала у всех декад подряд. Теперь она считается по средней
   скорости ветра — именно для неё сформулирован критерий суховея (≥ 5 м/с).
3. **Суховейные сутки** определялись по средним за декаду значениям, то есть
   декада целиком объявлялась суховейной или не суховейной. Теперь данные
   почасовые, и сутки помечаются по настоящему синоптическому критерию:
   не менее 3 часов с T ≥ 25 °C, влажностью ≤ 30 % и ветром ≥ 5 м/с одновременно.

## Как именно используется сеть

Архитектура и константы считаны прямо из ZIP/pickle-контейнера чекпойнта:
сеть 13 → 64 → 128 → 64 → 32 → 1 с BatchNorm и ReLU, плюс физические константы
RUSLE `K=0.3`, `LS=1.1907`, `P=0.8`, `max_rusle=erosion_scale=4.2866`.
Модель предсказывает безразмерный индекс эрозионной деградации почвы,
физически увязанный с уравнением RUSLE `A = R·K·LS·C·P`.

Откуда берутся 13 признаков:

| №       | Признак                                                                | Источник                                                                                                                                |
| ------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 0       | `R_factor`                                                             | эрозивность осадков за декаду, `R = Σ α·P^β` по суткам с осадками ≥ 10 мм (суточная модель EI30)                                        |
| 1, 2, 4 | `K`, `LS`, `P`                                                         | константы из самого чекпойнта                                                                                                           |
| 3       | `C_factor`                                                             | RUSLE C по фенологической кривой покрова, с поправкой на тепло и влагообеспеченность; можно задать вручную (`--cover` или `--c-factor`) |
| 5-11    | осадки, норма, температура, аномалия, ветер, порывы, влажность воздуха | декадная агрегация Open-Meteo                                                                                                           |
| 12      | `soil_moisture_frac`                                                   | `soil_moisture_0_to_7cm` из архива Open-Meteo                                                                                           |

**Честно про калибровку.** В чекпойнте не сохранён scaler входных признаков,
поэтому точный масштаб обучающей выборки восстановить невозможно — это свойство
файла, а не недоработка. Масштабирование подобрано по косвенным признакам:
`max_rusle = 4.2866` при `K·LS·P = 0.2857` означает, что при `C ≤ 1` величина `R`
на обучении доходила примерно до 15-60, то есть подавалась в физических
единицах. Поэтому RUSLE-факторы оставлены в натуральных единицах, а метеопризнаки
нормируются min-max по явным физическим диапазонам (`FEATURE_RANGES`
в `src/features.py` — один словарь, правится под свой регион).

Сырой выход сети при этом не лежит в [0, 1], поэтому по умолчанию он переводится
в индекс перцентилем внутри собственной климатической выборки этой же точки
(`--pinn-calibration climatology`): 0 — самая спокойная декада выборки, 1 — самая
эрозионно-напряжённая. Ранжирование целиком делает сеть, перцентиль лишь убирает
неизвестный сдвиг и масштаб — тот же приём, что применяется в SPI для осадков.
Альтернативы: `sigmoid` и `raw` (для отладки). Сырой выход сети в любом случае
попадает в отчёт колонкой `pinn_raw_output`, рядом с физической оценкой
`rusle_A_norm` — их можно сравнивать между собой.

На тестовой выборке из 145 декад ранговая корреляция между индексом сети и её
собственной физической оценкой `A/max_rusle` составила **0.79**: сеть и
уравнение RUSLE ранжируют декады согласованно, то есть препроцессинг собран
непротиворечиво.

Индекс деградации поднимает композитный риск максимум на 15 %
(`DEGRADATION_BOOST` в `src/decadal_risk.py`): деградированная почва хуже держит
влагу и сильнее подвержена ветровой эрозии.

## Веб-интерфейс

```bash
cd agrorisk
pip install -r requirements.txt
python web.py
```

Браузер откроется сам на `http://127.0.0.1:8000/`. В Windows достаточно
дважды кликнуть `start-web.bat`.

Что на странице:

- **Поиск места.** Наберите название — подсказки подтянутся из геокодера
  Open-Meteo; можно ввести и пару координат. Выбранная точка запоминается.
- **Лента декад** — главный экран. Один столбец = одна декада, высота столбца
  равна композитному индексу, цвет — категория риска по шкале созревания хлеба
  от зелёного до выжженного. Штриховкой помечены декады, посчитанные по
  прогнозу. Пунктиры на отметках 40 и 60 показывают границы «повышенного» и
  «высокого» риска. Столбцы выбираются мышью, Tab и стрелками.
- **Карточка декады** под лентой: композитный индекс, три под-индекса, осадки
  против нормы, влажность почвы, число суховейных суток, индекс деградации
  почвы с нейросети и текстовые пометки о том, что именно не так.
- **Таблица всех декад** и кнопка выгрузки CSV.

Пока идёт расчёт, на странице видны те же шаги, что печатает консольная
версия. Первый запуск по новой точке занимает до минуты: тянутся два года
почасовых данных и климатическая норма.

Сервер поднят на `http.server` из стандартной библиотеки — ни Flask, ни
чего-либо ещё ставить не нужно, а сама страница не обращается ни к одному
внешнему адресу, поэтому интерфейс открывается и без интернета (данные,
разумеется, без сети не придут). Ключи: `--port`, `--host 0.0.0.0` (открыть
доступ с других машин в локальной сети), `--no-browser`.

## Запуск из командной строки

```bash
python run.py
```

Больше ничего вводить не нужно: программа спросит населённый пункт, найдёт его
координаты геокодером Open-Meteo, сама подхватит лежащий рядом `pinn_model.pt`,
включит прогноз и запомнит точку — в следующий раз хватит одного Enter.

```bash
python run.py                    # спросит место (или Enter — прошлое)
python run.py Акколь             # место прямо в команде
python run.py "51.17 71.45"      # или координаты, если они известны
python run.py --yes              # совсем без вопросов: прошлая точка и значения по умолчанию
```

В Windows можно просто дважды кликнуть по `start.bat`.

Если название неоднозначное, программа покажет список и предложит выбрать
номер; Enter выбирает первый, самый крупный населённый пункт.

На выходе — таблица в консоли и `risk_report.csv` с композитным индексом
(0-100), категорией (низкий / умеренный / повышенный / высокий / критический),
тремя под-индексами, индексом деградации почвы и исходными декадными величинами.

Все ключи необязательные — они нужны только для тонкой настройки:

| Ключ                                           | Назначение                                   | По умолчанию              |
| ---------------------------------------------- | -------------------------------------------- | ------------------------- |
| `--lat` / `--lon`                              | координаты вместо названия                   | ищутся по названию        |
| `--farm`                                       | название хозяйства в отчёте                  | название места            |
| `--model`                                      | путь к `pinn_model.pt`                       | ищется рядом с программой |
| `--no-model`                                   | считать без нейросети                        | модель подключается       |
| `--forecast-days`                              | досчитать N суток прогноза, 0-16             | 10                        |
| `--history-days`                               | глубина отчёта в сутках                      | 60                        |
| `--climatology-years`                          | глубина климатической нормы                  | 15                        |
| `--calibration-days`                           | окно калибровки выхода сети                  | 730                       |
| `--backend auto\|torch\|numpy`                 | чем считать сеть                             | torch, если установлен    |
| `--pinn-calibration climatology\|sigmoid\|raw` | перевод выхода сети в индекс 0..1            | climatology               |
| `--cover` / `--c-factor`                       | покров или RUSLE C вручную, например по NDVI | по фенологической кривой  |
| `--first-snow-doy`                             | климатический день года первого снега        | 300 (≈27 октября)         |
| `--sukhovey-min-hours`                         | часов условий суховея для суховейных суток   | 3                         |
| `--yes`                                        | не задавать вопросов                         | вопросы задаются          |

**torch не обязателен.** Инференс реализован двумя бэкендами: torch и чистый
numpy (тот же прямой проход, Linear/ReLU/BatchNorm в режиме eval). Без torch
программа работает полностью; torch нужен только для дообучения
(`pinn_model.finetune`) и сохранения нового чекпойнта.

Запросов к Open-Meteo делается три: геокодер (если место задано названием),
почасовой архив за калибровочное окно и суточный архив за N лет для нормы,
плюс четвёртый на прогноз.

### Если в подсказке видно `--notify-config`

Значит запускается **старая** версия `main.py` — в новой этого ключа нет.
Проверить просто: новая версия первой строкой печатает `Агрориск 2.0`.
Распакуйте архив в чистую папку и запускайте `run.py` из неё; если старая
копия осталась рядом, удалите её вместе с `src/notifications.py` и папкой
`config/`.

## Проверка работоспособности

```bash
python tests/test_offline.py
```

31 проверка: чтение настоящего чекпойнта, совпадение бэкендов torch и numpy,
сборка признаков, под-индексы, поиск места по названию, автопоиск модели,
запоминание настроек, устойчивость клиента к недоступной переменной и к обрыву
сети, сквозной прогон конвейера, а также веб-слой — реальный HTTP-цикл на
свободном порту: статус, подсказки, запуск расчёта, опрос хода, выгрузка CSV,
понятные тексты ошибок и автономность страницы. Сетевой клиент в тесте
подменяется заглушкой с синтетическим, но реалистичным ответом Open-Meteo —
нейросеть при этом берётся настоящая, из `pinn_model.pt`.

Так проверен весь конвейер, **кроме самих сетевых вызовов**: в среде, где
собиралась эта версия, не было доступа к `open-meteo.com`, поэтому реальные
ответы API мною не проверялись. По той же причине страница не открывалась в
настоящем браузере — её разметка и скрипты проверены разбором, а API под ней
прогнан по-настоящему, через HTTP. Имена переменных и единицы выставлены по
документации Open-Meteo, а клиент дополнительно умеет выбросить переменную,
которую API не принял, и повторить запрос — так что расхождение в одном
параметре не уронит расчёт.

## Что стоит донастроить под своё хозяйство

1. **Число полей** — сейчас одна точка; для нескольких оберните
   вызов `run_analysis()` в цикл по списку координат.
2. **`--first-snow-doy`** — климатическая дата первого снега по местной норме,
   а не значение по умолчанию (≈27 октября).
3. **`RISK_WEIGHTS`** в `src/decadal_risk.py` — сейчас 45/35/20
   (засуха/суховей/снег), подберите под приоритеты хозяйства.
4. **`FEATURE_RANGES`** и кривая покрова `COVER_CURVE_*` в `src/features.py` —
   под свой климат и севооборот; при наличии NDVI лучше подать покров напрямую
   через `--cover`.
5. **Дообучение.** Когда накопятся факты по декадам (зафиксированная эрозия,
   урожайность), `pinn_model.finetune()` дообучит сеть с physics-informed loss,
   а `save_checkpoint()` сохранит результат в формате исходного файла. Это
   снимет и неопределённость с масштабом признаков: scaler станет вашим.
